# Author background seeds

**Purpose:** Manually editable background for Author task selection, read only when relevant. Not a developer profile, capability assessment, or mandatory prompt template.

**Source:** v0.2 §1.2 in the user-provided pasted-text attachment. This file preserves the self-reported background and candidate directions recorded there; not every item is the goal of the current exercise.

## Relevant background available for use

The user has professional experience with Java/Spring Boot backends, API and specification design, external-system integration, flow and error handling, testing, and code changes.

They want practice beyond implementing APIs from specifications and want substantive engineering cases to discuss. Go has been a technology of interest; this does not require the platform or baseline to use Go.

The user practices with their own IDE and coding agent. The platform does not need to limit AI participation or determine which parts the user wrote themselves.

## Exercise preferences

Use a real codebase and retain the interest of actually operating, investigating, and changing a system. Keep exercises focused but technically deep, with evidence available in code, data, and runtime behavior. Accept different reasonable solutions.

Do not reduce exercises to random bug injection or constant-changing puzzles. Do not manufacture difficulty through more modules, more architecture, or slower AI solving. See [Platform agent guidance](../docs/agents.md) for quality principles.

## Candidate directions, not a scheduled curriculum

Cross-module analysis, data consistency, concurrency/background work, design tradeoffs, and delivery verification are previously discussed candidates. The current user request and baseline capabilities determine which apply and how far the exercise goes.

Do not infer that the user does not understand transactions, has mastered a pattern, or must follow a career path. Without a specific request, the Author may select within the supplied brief; it need not first collect a complete learning history.

## Maintenance

The user explicitly supplies or changes background and direction. Engineering review feedback does not automatically rewrite this file, create a capability profile, or recommend the next exercise.

This file contains personal preferences and is authoring/platform-design material, not learner-repository content. If platform documentation becomes public, the user decides whether to retain this personalized material.
